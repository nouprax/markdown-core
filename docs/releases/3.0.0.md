# Markdown Core 3.0.0

Markdown Core 3.0.0 is the renamed, parser-only continuation of the cmark-gfm
engine, extended with tables, strikethrough, autolinks, task lists, formulas,
and directives. It publishes the same parsing model for C, Swift, Kotlin, and
ECMAScript/Wasm.

## Parser and API

- Parsing is one synchronous source-to-document operation. The render surface
  and the feed, stream, edit, session, snapshot, and delta lifecycles are not
  part of this release.
- The formula and directive extensions have explicit grammars and no longer
  alter CommonMark emphasis merely by being enabled.
- The CommonMark layer is synchronized from cmark 0.29 through stable cmark
  0.31.2, including its parsing, security/complexity, Unicode 17, entity, and
  scanner changes. cmark-gfm remains authoritative only for GFM extensions.
- References, definitions, directive labels, and directive attributes remain
  represented in the immutable AST instead of being flattened into unrelated
  values. `DirectiveLabel` is `Markup` held by the directive's typed `label`
  field; it is not part of the directive's `content`. Directive attributes
  preserve first-occurrence source order.
- Source positions, optional strings, empty destinations, and normalized
  association identifiers have one shared meaning in every language binding.
- The ECMAScript adapter transfers a complete AST in one Wasm call through an
  ES-private indexed linear-memory table. Transfer cost no longer scales in
  host-to-Wasm calls per node or field.
- JVM and Android now register their single bulk JNI method from `JNI_OnLoad`;
  their package-private `byte[]` payload belongs only to that boundary, the
  packaged native library exports only the loader hook, and the Android
  publication ships the exact R8 name-preservation rule it requires.
- Kotlin/Native directly cinterops the read-only C facade, copies borrowed AST
  fields into Kotlin values with iterative materialization, and releases the C
  document on every exit path.
- ES/Wasm, JVM/Android JNI, and Kotlin/Native deliberately do not share a
  binding bridge or transport ABI; they share only the canonical AST contract.
- Native formula postprocessing and every language-binding projection are
  stack-safe for the uncapped parser depth; all bindings exercise a 10,000-level
  nested-list document.
- Kotlin publication documentation selects `docs/releases/3.0.0.md` from the
  root `VERSION`; no artifact packages a deprecated migration document.
- Several inherited names and binding properties were renamed to match that
  shared model. This is a source-breaking major release.

## Failure and concurrency

- Allocation failure is terminal and is returned directly to the consumer.
  The parser does not retry, sort, linearly scan, or otherwise fall back after
  an allocation has failed.
- Independent parser instances can execute concurrently. Parser options,
  extensions, allocation state, and failure state are owned by the parse
  transaction rather than writable process-global state.

## Platforms

- Swift uses Swift tools 6.3 and supports iOS 26 and macOS 26.
- Kotlin publications use AGP 9.3.2 and Kotlin Gradle Plugin 2.4.10 while
  preserving the documented Java and Kotlin consumer compatibility floors.
- The ECMAScript package is built with Emscripten 6.0.9 and supports Node.js
  and browsers through the same Wasm parser.

See `CHANGELOG.md` for the complete list of public model and parser changes.
