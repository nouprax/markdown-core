# Markdown Core 3.0.0

**In development.** The tag `v3.0.0` does not exist yet, and this note
accumulates as the work lands. `VERSION` names 3.0.0 because that is what this
tree is becoming and because no smaller number is honest: the engine is
reconstructed from the 1.0 baseline and its parse output already differs from
1.0.3 in ways a patch number cannot describe.

The 2.0.0 line is withdrawn. Its major version was bought with a session and
incremental parsing API that no longer exists.

## Corrections to the parse

Each of these changes what this parser answers for some input, and each is
covered by a test that fails without it.

- A footnote call whose label crosses a line ending keeps its bytes.
  `x[^a`⏎`b] tail` used to lose the label entirely and answer `x[^] tail`.
- A footnote label spelled with a character reference, such as `[&Hat;label]`,
  is read out of the source rather than out of a freed buffer. It previously
  produced NUL bytes in the document and read memory that had been released.
- A footnote definition repeated inside another no longer destroys the outer
  one. Repeated labels resolve to the definition that opens first, in document
  order, and the definition that does not win stays where it was written.
- An unresolved footnote call carries a source position instead of line zero.
- Attaching the formula or directive extension no longer changes what
  CommonMark emphasis means. Both extensions folded their own syntax bytes into
  the parser's flanking table, so `foo:_bar_` and `foo$_bar_` stopped
  emphasising, and control bytes in the input started emphasising, merely
  because an extension was attached.
- A directive's grammar follows micromark-extension-directive applied to code
  points: name rules, the one-, two- and three-colon forms, the `#` and `.`
  shorthands, `class` accumulation with last-value-wins elsewhere, and
  degradation that leaves the directive standing and the punctuation as prose.
- Attaching `formula` is the only switch the formula extension has. Five inline
  forms, four block forms, and one padding rule.
- A link reference definition and a footnote definition are nodes at the byte
  where their opening bracket was written, and nothing after the parse moves,
  reorders, renumbers or drops them. Five kinds carry both the label as the
  source spells it and the normalized identifier it matches by.
- `null` and `""` are different answers, and nothing folds one into the other.
  `null` means the source did not write the field; `""` means it wrote it and
  it was empty. `CodeBlock.info`, `CodeBlock.language`, `Link.title`,
  `Image.title` and `ReferenceDefinition.title` now say which of the two they
  are, rather than reporting absence for both.
- `[a]()` and `[a](<>)` report `destination=""`. They wrote a destination and
  wrote nothing in it; a link with no destination at all is a `LinkReference`.

## Internals

- The flanking scan tests its bound before reading, and an assertion under
  debug builds keeps that order.
- The directive extension no longer registers a byte its inline matcher cannot
  consume.
- One allocator model, supplied per parser. There is no process-global scratch
  allocator and no re-parse retry in the table extension.
- An extension is a compile-time descriptor in a fixed table. It is not
  registered, not looked up by name, carries no mutable state, and cannot
  express an order.

## Compatibility

**The public surface changes in this release, in every language.** 3.0.0 is
where the changes the reconstruction requires land, and consumers should pin
the released tag rather than a range. What moved:

**Five exported C symbols are gone**, taken from the 1.0.3 export list rather
than from memory:

- `markdown_core_document_root` is now `markdown_core_document_semantic`. The
  parse has two total views, and the old name did not say which one it handed
  back.
- `markdown_core_error_get_scope` is removed, and so is `ParseError.scope` in
  Swift, Kotlin and ECMAScript. A parse failure carries no scope: an input the
  parser could not turn into a document has no extent to point at.
- `markdown_core_node_directive_first_label_child` and
  `markdown_core_node_directive_first_content_child` are removed. A directive's
  label is a `DirectiveLabel` node in the child list, so ordinary traversal
  reaches it and the two splice accessors have nothing left to splice.
- `markdown_core_node_footnote_id` is replaced by
  `markdown_core_node_association`, which answers for all five kinds that carry
  a label and reports the label as written beside the normalized identifier it
  matches by. Neither derives the other.

**Eleven are added**: `markdown_core_document_semantic`,
`markdown_core_document_source`, `markdown_core_document_line_count`,
`markdown_core_document_line_start`, `markdown_core_document_diagnostic_count`,
`markdown_core_document_diagnostic_at`, `markdown_core_diagnostic_code_name`,
`markdown_core_node_association`, `markdown_core_node_definition_resource`,
`markdown_core_node_directive_attribute_at` and
`markdown_core_node_reference_form`.

**Signatures changed on symbols that kept their names.**
`markdown_core_node_code_block_properties`, `_link_properties`,
`_image_properties` and `_definition_resource` now report an optional string as
`markdown_core_optional_string` — a value beside a presence flag — so a
caller that passed a `markdown_core_string *` no longer compiles. That is
the point: `null` and `""` are different answers and nothing folds one into the
other.

**In the bindings**, `ParseOptions.dollarFormulaDelimiters` and
`ParseOptions.latexFormulaDelimiters` are removed from Swift, Kotlin and
ECMAScript. Attaching `formula` is the only switch the extension has.
`Link.destination` and `Image.source` are no longer optional. `Document` gains
`concrete`, the normalized source and its line index — the text a scope's line
and column are counted against, which is not the string that was passed in
wherever it held a NUL.

**A scope is a pair of line/column boundaries** saying which range of the source
an element occupies. It is not a byte range and no substring is taken with it,
so a block closed by a blank line ends at column 0 of that line.

The Kotlin native bridge's wire format is `MKC5`. It is internal to the binding
and no consumer reads it, but a mismatched pair of halves fails loudly rather
than decoding garbage.
